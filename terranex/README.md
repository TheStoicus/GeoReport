# TerraNex — начальная настольная оболочка

TerraNex — развиваемая на C++20 и Qt 6 настольная геологическая система. Этот каталог представляет **отдельную начальную Qt-программу** и не заменяет рабочее приложение GeoReport.

## Требования

- CMake 3.20 или новее
- C++20-компилятор
- Qt 6.6 с модулем Widgets
- CLion или другая среда с поддержкой CMake

## Сборка на macOS

Если Qt установлен в `/Users/al.deshkovets/Qt`, укажите путь к конкретной версии Qt в `CMAKE_PREFIX_PATH`. Для установленного Qt 6.6.1 путь имеет вид:

```text
/Users/al.deshkovets/Qt/6.6.1/macos
```

Из корня репозитория:

```bash
cmake -S terranex -B build-terranex \
  -DCMAKE_PREFIX_PATH="/Users/al.deshkovets/Qt/6.6.1/macos"
cmake --build build-terranex
ctest --test-dir build-terranex --output-on-failure
```

Если используете CLion, откройте каталог репозитория или непосредственно каталог `terranex`, затем настройте CMake-профиль с тем же `CMAKE_PREFIX_PATH`. После изменения CMake перезагрузите проект.

## Текущее состояние

Реализованы:
- отдельная точка входа Qt;
- главное окно и меню;
- выбор папки проекта;
- первая независимая от Qt доменная модель: месторождение, блоки, скважины и пробы;
- связь скважины с несколькими блоками;
- раздельное хранение лабораторных параметров ГОСТ и СП;
- проверка базовой целостности данных и модульный тест через CTest.

Модель сохраняет координаты как числа с плавающей точкой без округления. Идентификаторы сущностей отделены от отображаемых номеров. Валидатор сообщает о некорректных интервалах проб, повторяющихся идентификаторах и ссылках на отсутствующие сущности; он не исправляет данные автоматически.

Пока **не реализованы** импорт Excel, БД PostgreSQL/PostGIS, геологические расчёты, карты и формирование отчётов. Не следует использовать эту оболочку как замену GeoReport для производственных расчётов.

## Принцип миграции

1. Сохранить GeoReport как контрольную рабочую версию.
2. Зафиксировать эталонные входные книги и результаты.
3. Выделять доменную модель и прикладные сценарии без изменения расчётных правил.
4. Переносить функции небольшими этапами и сравнивать результаты с GeoReport.
5. Подключать хранилище и графический интерфейс после появления стабильных контрактов данных.

См. также `ARCHITECTURE_MIGRATION.md` в корне репозитория.
