# GeoReport

GeoReport — консольное C++20-приложение для обработки инженерно-геологических данных из Excel, формирования геологической модели по скважинам, расчёта основных показателей и подготовки Excel/DXF-результатов.

Проект построен так, чтобы правила классификации не были зашиты в один калькулятор. Пользователь перед расчётом задаёт через консоль:

- какие породы считать полезным ископаемым;
- каким способом определять внешнюю вскрышу;
- какие породы считать вскрышными при режиме «по типу породы»;
- какие типы принудительно исключить в подстилающие;
- как поступать со специальной поверхностной пробой 0.00–0.50 м и как определять фактический ПРС;
- какой стандарт использовать для классификации песка;
- какие классы песка считать полезными;
- как учитывать грунтовые воды;
- учитывать ли сухое и обводнённое ПИ;
- какую сухую подушку оставить над расчётным УГВ;
- каким оборудованием ведётся разработка и сколько обводнённого ПИ допускается учитывать.

## 3. Предметная модель

### `Sample`

Один лабораторный образец.

Хранит:

- номер образца;
- интервал отбора;
- мощность;
- название грунта по ГОСТ;
- название грунта по ТКП;
- параметры ГОСТ;
- параметры ТКП.

Методы:

- `isMonolith()` — определяет монолит по начальному `м`/`М`;
- `isAgSample()` — определяет специальный образец `аг`;
- `isSurfaceSample()` — проверяет интервал 0.00–0.50 м;
- `getSoilType()` — возвращает ГОСТ-название, а при его отсутствии ТКП-название;
- `getRockType()` — нормализует название до базового типа (`Песок`, `Супесь`, `Суглинок`, `Глина`) либо возвращает исходное название;
- `getGostSandClass()` — классифицирует песок по ГОСТ;
- `getTkpSandClass()` — классифицирует песок по ТКП;
- `set/findGOSTParameter()` и `set/findTKPParameter()` — работа с лабораторными параметрами.

### `Borehole`

Одна скважина.

Содержит:

- номер;
- образцы;
- абсолютную отметку устья;
- глубину скважины;
- глубину и абсолютную отметку УГВ;
- координаты SK1963/WGS84.

### `Block`

Блок месторождения. Хранит название блока и номера относящихся к нему скважин.

Одна скважина может принадлежать нескольким блокам.

### `Deposit`

Корневая модель месторождения. Владеет всеми `Borehole` и `Block`.

## 4. Правила вскрышных пород

Поддерживаются два режима.

### 4.1. Фиксированная мощность

Пользователь задаёт, например:

```text
0.5 м
0.8 м
1.0 м
```

Вся толща от 0 до указанной границы классифицируется как внешняя вскрыша. Если лабораторная проба пересекает эту границу, она будет разделена.

### 4.2. По типам пород

Программа собирает реальные типы пород из исходного Excel и показывает их пользователю.

Например:

```text
1 — Песок
2 — Суглинок
3 — Супесь
4 — Глина
```

Можно выбрать несколько типов.

Если выбран режим по типам пород и полезное ископаемое начинается непосредственно под ПРС, можно задать минимальную мощность внешней вскрыши, например 0.8 м. Если фактическая граница ПИ находится раньше, она будет перенесена до минимальной границы, а проба будет разделена. Значение 0 отключает это правило.

Выбранные типы:

- выше ПИ становятся внешней вскрышей;
- внутри контура ПИ становятся неоднозначными и требуют решения пользователя;
- ниже ПИ относятся к подстилающим.

Обычная неполезная порода выше ПИ также является внешней вскрышей.

## 5. Правила полезного ископаемого

Пользователь вручную выбирает типы пород, которые являются ПИ.

Поддерживаются как стандартные типы:

- Песок;
- Супесь;
- Суглинок;
- Глина;

так и любые нестандартные текстовые типы, присутствующие в лаборатории.

Для песка дополнительно можно выбрать источник классификации:

1. ГОСТ;
2. ТКП;
3. ГОСТ или ТКП.

Для строительных материалов рекомендуется режим ГОСТ.

### Классы ГОСТ

- очень тонкий;
- тонкий;
- очень мелкий;
- мелкий;
- средний;
- крупный;
- повышенной крупности.

### Классы ТКП

- пылеватый;
- мелкий;
- средний;
- крупный;
- гравелистый.

Если класс песка известен и пользователь его не включил, образец не считается ПИ.

## 6. Подстилающие породы

Основное правило:

> Всё, что находится ниже последнего окончательного интервала полезного ископаемого и не является частью учитываемого ПИ, относится к подстилающим породам.

Пользователь может дополнительно выбрать типы, которые принудительно исключаются из ПИ и назначаются подстилающими.

Кроме обычных пород в подстилающую толщу могут попасть части самого полезного ископаемого, которые не вошли в расчётную добываемую толщину:

- обводнённая часть при режиме `DryOnly`;
- сухая часть защитной подушки над УГВ;
- обводнённая часть сверх ограничения оборудования.

Это реализовано в `UnderlyingRockResolver`.

## 7. Поверхностный образец и ПРС

Интервал `0.00–0.50 м` распознаётся как специальный поверхностный образец только для отдельного правила обработки такой пробы.

**ПРС не задаётся фиксированной мощностью 0.50 м.**

ПРС определяется по фактическому верхнему неопробованному интервалу скважины:

```text
0.00–0.20 м не опробовано -> ПРС = 0.20 м
0.00–0.30 м не опробовано -> ПРС = 0.30 м
0.00–0.50 м не опробовано -> ПРС = 0.50 м
проба начинается с 0.00 м -> ПРС отсутствует
```

Это принципиально отделяет ПРС от обычной внешней вскрыши. Если верхняя проба начинается с 0.20 м, программа не увеличивает ПРС искусственно до 0.50 м.

Пользователь отдельно выбирает, как обрабатывать специальную пробу `0.00–0.50 м`:

1. исключить из классификации;
2. считать ПИ;
3. считать внешней вскрышей.

`АГ` и монолиты полностью исключаются из геологической классификации.

## 8. Неоднозначные интервалы

Если неполезная порода находится внутри контура ПИ, автоматически принимать решение нельзя.

Такой интервал получает тип:

```text
Ambiguous
```

`SectionDecisionProvider` задаёт вопрос в консоли:

```text
Скважина 26: неоднозначный интервал 4.9–6.3 м
1 — полезное ископаемое
2 — внутренняя вскрыша
```

После ответа `BoreholeSectionResolver` строит окончательную модель.

Тестовое жёстко заданное правило для скважины 26 удалено: теперь решение принимает пользователь.

## 9. Правила образцов

После построения окончательной модели `SampleSplitter` находит все границы между средами.

Если проба пересекает границу, например:

```text
Проба: 3.0–6.0 м
Граница: 4.5 м
```

получаются:

```text
исходная проба: 3.0–4.5 м
дочерняя проба: 4.5–6.0 м
```

Номер дочерней части получает суффикс:

```text
а, б, в, г, ...
```

Лабораторные свойства полностью копируются.

`АГ` не разделяется.

После этого в результирующий Excel автоматически добавляются два прозрачных листа:

- `GOST_split`;
- `TKP_split`.

Все последующие расчёты работают с изменённым `Deposit`, то есть с уже разделёнными образцами.

## 10. Грунтовые воды

`GroundwaterAnalysis` поддерживает три режима.

### Automatic

По умолчанию можно считать УГВ преобладающим, если его вскрывает не менее заданной доли скважин.

Например:

```text
50 %
60 %
70 %
```

В среднее входят только скважины, реально вскрывшие УГВ.

### MeanLevel

Средний абсолютный уровень УГВ используется принудительно.

### IndividualLevel

Каждая скважина использует собственный УГВ.

При среднем режиме расчёт выполняется по абсолютной отметке УГВ:

```text
средняя отметка УГВ = среднее абсолютных отметок
```

Для скважины расчётная глубина:

```text
глубина УГВ = отметка устья - средняя отметка УГВ
```

Это позволяет корректно работать с разными отметками устьев.

## 11. Сухая и обводнённая часть ПИ

Пользователь выбирает:

### DryAndWaterBearing

Учитываются сухое и обводнённое ПИ.

### DryOnly

В расчёт ПИ входит только сухая часть.

Дополнительно задаётся сухая подушка над УГВ, например:

```text
0.5 м
0.8 м
1.0 м
```

Граница сухого ПИ:

```text
УГВ - сухая подушка
```

Часть между этой границей и УГВ не теряется: она передаётся в подстилающие породы.

## 12. Ограничение по оборудованию

`DevelopmentSettings` поддерживает:

- пользовательское ограничение;
- экскаватор — 2.5 м обводнённого ПИ;
- земснаряд / без ограничения.

При ограничении обводнённого ПИ оставшаяся часть не пропадает. Она передаётся в подстилающую толщу.

## 13. Excel

`ExcelReader` читает исходные 5 листов:

1. журнал блоков и скважин;
2. координаты и паспорт;
3. описание слоёв — пока резервируется;
4. лаборатория ГОСТ;
5. лаборатория ТКП.

`ExcelWriter` записывает результат на основе `template.xlsx`.

Основные результаты:

- лист 1 — основные показатели;
- лист 4 — результаты по пробам/скважинам;
- лист 5 — результаты по блокам;
- лист 9 — гранулометрический состав;
- разделённые лабораторные листы — промежуточные данные после `SampleSplitter`.

### Лист 1

20 основных колонок:

1. № п/п;
2. № блока;
3. № выработки;
4. глубина выработки;
5. абсолютная отметка устья;
6. мощность вскрышных пород;
7. ПРС;
8. абсолютная отметка кровли ПИ;
9. общая мощность ПИ;
10. мощность сухого ПИ;
11. мощность обводнённого ПИ;
12. абсолютная отметка подошвы ПИ;
13. глубина УГВ;
14. абсолютная отметка УГВ;
15. мощность подстилающих пород;
16. название подстилающих пород;
17. отметка кровли сухого ПИ;
18. отметка подошвы сухого ПИ;
19. отметка кровли обводнённого ПИ;
20. отметка подошвы обводнённого ПИ.

Если скважина принадлежит нескольким блокам, например `IIIB` и `IVC1`, в колонке блока записывается:

```text
IIIB, IVC1
```

## 14. DXF

`DxfWriter` создаёт план расположения скважин.

Правила:

- слой `BOREHOLES`;
- входные координаты SK1963;
- DXF X = исходный Y;
- DXF Y = исходный X;
- Z = 0;
- диаметр скважины = 4;
- высота текста = 12.5;
- номер скважины располагается слева;
- абсолютная отметка располагается ниже.

`DxfColumnWriter` создаёт геологические колонки по окончательной геологической модели.

## 15. Назначение каждого файла

### `main.cpp`
Точка входа. Находит корень проекта, читает Excel, получает все пользовательские настройки, запускает анализ и создаёт Excel/DXF.

### application

`BoreholeAnalysisResult.h/.cpp` — единый результат одной скважины: классификация, геология и основные показатели.

`GeologicalAnalysisResult.h/.cpp` — контейнер результатов всех скважин.

`GeologicalAnalysisService.h/.cpp` — оркестратор полного процесса. Не содержит правил классификации, а только связывает компоненты.

### domain

`Sample` — лабораторная проба.

`Borehole` — скважина.

`Block` — блок месторождения.

`Deposit` — месторождение.

`BoreholeSection` — интервал геологической модели и его тип.

`GeologicalSection` — базовый интервал с кровлей, подошвой и мощностью.

`SurfaceSoil` — ПРС.

`Overburden` — внешняя или внутренняя вскрыша.

`UsefulMineral` — контейнер сухого и обводнённого ПИ.

`DryMineralSection` — сухой участок ПИ.

`WaterBearingMineralSection` — обводнённый участок ПИ.

`UnderlyingRock` — подстилающий интервал.

### settings

`MainIndicatorsSettings` — все правила геологической классификации: вскрыша, ПИ, песок, подстилающие, поверхностная проба.

`ConsoleSettingsReader` — интерактивный ввод настроек.

`GroundwaterCalculationSettings` — режим расчёта среднего/индивидуального УГВ и порог большинства.

`GroundwaterSettings` — режим включения обводнённого ПИ и сухая подушка.

`DevelopmentSettings` — ограничения оборудования.

### geology

`SectionClassifier` — первичная классификация интервалов.

`SectionDecision` — решение по неоднозначному интервалу.

`SectionDecisionProvider` — получение решений пользователя.

`BoreholeSectionResolver` — превращает первичную классификацию + решения в окончательную модель.

`BoreholeGeology` — агрегированная геология скважины.

`BoreholeGeologyResolver` — собирает ПРС, вскрышу, ПИ и подстилающие.

`SurfaceSoilResolver` — выделяет ПРС.

`OverburdenResolver` — выделяет внешнюю/внутреннюю вскрышу.

`UsefulMineralResolver` — разделяет ПИ на сухое и обводнённое с учётом УГВ и оборудования.

`UnderlyingRockResolver` — формирует подстилающую толщу, включая части ПИ, не вошедшие в расчётную добываемую толщину.

### calculations

`BoreholeSectionAnalyzer` — анализирует все скважины и запускает интерактивные решения.

`BoreholeSectionAnalysis` — состояние анализа одной скважины.

`SampleSplitter` — разделяет лабораторные пробы по границам геологических сред.

`GroundwaterAnalysis` — определяет режим УГВ и средний уровень.

`MainIndicatorsCalculator` — рассчитывает основные показатели.

`WeightedAverageCalculator` — средневзвешенные лабораторные параметры.

`GranulometricCompositionCalculator` — расчёт гранулометрического состава.

### excel

`ExcelReader` — импорт исходного Excel.

`ExcelWriter` — общий экспорт результата.

`ExcelCellUtils` — безопасное чтение Excel-значений.

`ExcelWriteUtils` — запись строк/чисел и округление.

### writers

`MainIndicatorsResultWriter` — лист основных показателей.

`BoreholeResultWriter` — результаты по скважинам.

`BlockResultWriter` — результаты по блокам.

`GranulometricCompositionWriter` — лист гранулометрии.

`SplitLaboratoryWriter` — лаборатория после разделения проб.

### results

`MainIndicators` — рассчитанные показатели одной скважины.

`BoreholeResult` — средневзвешенные показатели одной скважины.

`WeightedAverageResult` — набор средневзвешенных значений.

### graphics/dxf

`DxfDocument` — внутреннее представление DXF-документа.

`DxfLayer` — слой DXF.

`DxfWriter` — план расположения скважин.

`DxfColumnWriter` — геологические колонки.

### utils

`ParameterValue` — `variant`: пустое значение, число или текст.

`SandClassification` — классификация песков по ГОСТ/ТКП.

## 16. Зависимости

### Обязательные

- C++20;
- CMake 3.20+;
- OpenXLSX;
- стандартная библиотека C++.

## 21. Важные инженерные принципы

1. АГ не участвуют в классификации и расчётах.
2. Монолиты не участвуют в расчётах мощности и средневзвешенных показателей.
3. Нельзя автоматически превращать неоднозначную породу внутри ПИ во вскрышу или ПИ — решение задаётся пользователем.
4. Подстилающая порода определяется относительно окончательной подошвы ПИ.
5. Неучтённая часть полезной толщи не теряется: она передаётся в подстилающие породы.
6. Средний УГВ рассчитывается только по скважинам, вскрывшим воду.
7. При среднем УГВ для конкретной скважины используется абсолютная отметка среднего уровня.
8. Все границы геологических сред проходят через `SampleSplitter` до лабораторных расчётов.
9. Excel-вывод использует результаты той же модели, которая используется для DXF.
10. Скважина может принадлежать нескольким блокам; все блоки записываются в одну ячейку через запятую.

## 22. Где менять алгоритм в будущем

Если появится графический интерфейс, менять расчётную модель не требуется.

Основные точки расширения:

- вместо `ConsoleSettingsReader` подключается GUI-настройка;
- вместо консольного `SectionDecisionProvider` подключается диалоговый интерфейс;
- `MainIndicatorsSettings` остаётся единым хранилищем правил;
- `GeologicalAnalysisService` остаётся оркестратором;
- Excel и DXF используют тот же `GeologicalAnalysisResult`.

Это позволяет впоследствии добавить отдельное приложение для проектирования/горных работ, не разрушая геологическое ядро GeoReport.

## Дополнительные правила расчёта (актуальная версия)

### 1. Выбор песка

Песок не является единственным неделимым пунктом выбора. При настройке полезного ископаемого пользователь выбирает конкретные классы песка.

ГОСТ:

1. Очень тонкий
2. Тонкий
3. Очень мелкий
4. Мелкий
5. Средний
6. Крупный
7. Повышенной крупности

ТКП:

1. Пылеватый
2. Мелкий
3. Средний
4. Крупный
5. Гравелистый

Дополнительно доступны глинистые грунты ТКП:

- Супесь
- Суглинок
- Глина

Для вскрышных и подстилающих пород песок также может назначаться по конкретному классу, а не только целиком как базовый тип.

### 2. Фактический и расчётный УГВ

В модели одновременно существуют два понятия:

- **фактический УГВ** — значение конкретной скважины из исходного Excel;
- **расчётный УГВ** — индивидуальный или средний уровень, выбранный режимом расчёта.

Если принят режим среднего уровня, средняя абсолютная отметка УГВ рассчитывается только по скважинам, в которых УГВ действительно вскрыт. Скважины без вскрытого УГВ в среднем не участвуют.

При этом в таблице основных показателей и в обозначениях, относящихся непосредственно к паспорту скважины, сохраняется фактическое значение УГВ конкретной скважины.

Для разделения полезного ископаемого на сухую и обводнённую части используется именно **расчётный** уровень УГВ.

### 3. ПРС

ПРС больше не определяется фиксированным значением 0.50 м.

ПРС равен фактической мощности верхнего неопробованного интервала:

```text
первая обычная проба начинается с 0.20 м → ПРС = 0.20 м
первая обычная проба начинается с 0.30 м → ПРС = 0.30 м
первая обычная проба начинается с 0.00 м → ПРС = 0.00 м
```

Монолиты и АГ не считаются обычным опробованием для этого определения.

### 4. Средневзвешенные значения

Средневзвешенные показатели рассчитываются **только по полезному ископаемому**.

Это означает, что если один исходный лабораторный образец пересекает границу геологических сред, в расчёт попадает только его часть, которая относится к ПИ.

Например:

```text
образец:             5.0–8.0 м
граница вскрыша/ПИ:  6.0 м
граница ПИ/подстил.: 7.0 м

5.0–6.0 м → вскрыша       → не участвует
6.0–7.0 м → ПИ            → участвует
7.0–8.0 м → подстилающая  → не участвует
```

Если лабораторный параметр имеет значение во всём исходном образце, для средневзвешенного используется только мощность полезной части образца.

Формула:

```text
                    Σ(value × полезная мощность)
СВ = -------------------------------------------------------
                    Σ(полезная мощность)
```

Монолиты и АГ полностью исключаются.

Та же логика используется для:

- средневзвешенных значений по скважине;
- средневзвешенных значений по блоку;
- итогового гранулометрического состава по блоку.

### 5. Координаты DXF

Координаты SK-1963 читаются как `double` и передаются в DXF без искусственного округления.

Преобразование для графики сохраняется:

```text
DXF X = исходная Y
DXF Y = исходная X
```

Форматирование координат выполняется через `std::to_chars`, чтобы не использовать стандартные шесть значащих цифр `ostream`, которые недостаточны для координат SK-1963.

### 6. Ответственность основных компонентов

`MainIndicatorsSettings` — хранит правила, какие типы и классы относятся к ПИ, вскрыше и подстилающим породам.

`ConsoleSettingsReader` — получает эти правила от пользователя.

`SectionClassifier` — классифицирует глубинные интервалы на основе проб и настроек.

`BoreholeSectionResolver` — превращает неоднозначные участки в окончательные интервалы после принятия решения.

`SampleSplitter` — делит лабораторные образцы по границам окончательной геологической модели.

`GroundwaterAnalysis` — определяет режим УГВ и среднюю абсолютную отметку по водоносным скважинам.

`UsefulMineralResolver` — делит ПИ на сухое и обводнённое с использованием расчётного УГВ.

`OverburdenResolver` — формирует внешнюю и внутреннюю вскрышу.

`UnderlyingRockResolver` — формирует подстилающую толщу, включая неучтённую при разработке часть интервала ПИ.

`WeightedAverageCalculator` — рассчитывает средневзвешенные лабораторные показатели только по полезной части образцов.

`MainIndicatorsCalculator` — формирует основные показатели скважины и сохраняет фактический УГВ.

`MainIndicatorsResultWriter` — записывает результаты на лист основных показателей и отдельно определяет фактический ПРС.

`BoreholeResultWriter` — формирует детальную таблицу лабораторных образцов.

`BlockResultWriter` — рассчитывает результаты по блокам на основании полезных интервалов.

`GranulometricCompositionCalculator` — формирует диапазоны и средневзвешенный гранулометрический состав по полезному ископаемому.

`DxfDocument` — отвечает за точное текстовое представление числовых координат и геометрии DXF.

# Изменения текущей версии

## Разделение лабораторных образцов

`SampleSplitter` вызывается **после формирования `BoreholeGeology`**, поэтому программа теперь знает все необходимые границы. Один исходный образец может быть разделён на несколько частей при пересечении:

- вскрыши и полезного ископаемого;
- сухого и обводнённого полезного ископаемого;
- полезного ископаемого и подстилающих пород.

Лабораторные характеристики копируются во все фрагменты, а номера получают суффиксы `а`, `б`, `в` и т.д.

## Листы со средневзвешенными показателями

На листе результатов по скважинам записываются только те образцы, которые имеют пересечение с окончательно выделенным полезным ископаемым. Образцы/фрагменты, относящиеся только к вскрыше, подстилающим породам или другим нерасчётным интервалам, в эту ведомость не записываются.

При этом отдельные разделённые лабораторные листы `GOST_split` и `TKP_split` сохраняют полный набор разделённых образцов, что позволяет проверить исходную лабораторную информацию и границы разделения.

Средневзвешенные значения рассчитываются только по части мощности, относящейся к полезному ископаемому.


## Последние правила расчёта средневзвешенных показателей

Средневзвешенные показатели считаются только по той части полезного ископаемого, которая реально входит в расчётную модель добываемого ПИ. В частности, учитываются сухие участки `UsefulMineral` и разрешённые обводнённые участки. Часть исходной пробы, которая отнесена к вскрыше, подстилающим породам, либо исключена ограничениями разработки, не получает веса в средневзвешенном расчёте и не записывается как проба ПИ в соответствующие ведомости.

## Шкала геологических колонок DXF

Для каждой скважины вертикальная шкала строится по абсолютным отметкам с шагом 1 метр. Верхняя отметка шкалы равна округлению отметки устья вверх до целого метра (`ceil`), нижняя — округлению отметки забоя вниз до целого метра (`floor`). Например, для устья 181.3 м и забоя 169.8 м шкала идёт от 182 до 169 м. Подписи целых абсолютных отметок располагаются слева от шкалы.
## Графика геологических колонок — текущий этап

- расстояние между колонками увеличено до 60 DXF-единиц;
- номер образца, его интервал и тип породы справа от колонки больше не выводятся;
- интервалы образцов отображаются непосредственно на стволе, а отметки границ задаются общей шкалой;
- фактический уровень грунтовых вод каждой скважины показывается синей штриховой линией;
- рядом с линией выводится синяя подпись вида `УГВ 176.50 м`;
- отдельная условная легенда пока намеренно не добавляется и будет сделана на следующем этапе.


## Дополнение: расчёт подблоков по обводнённости

Если в пределах исходного блока присутствуют и сухое, и обводнённое полезное ископаемое, исходный блок сохраняется как общий блок и дополнительно рассчитывается по двум производным подблокам:

- `Подблок <имя> — сухое ПИ`;
- `Подблок <имя> — обводнённое ПИ`.

Для каждого подблока отдельно определяются:

- список скважин, в которых присутствует соответствующая часть ПИ;
- расчётная мощность;
- средневзвешенные показатели ГОСТ;
- параметрическая расчётная мощность для каждого показателя.

Если в блоке имеется только сухое или только обводнённое ПИ, отдельные два подблока не создаются — сохраняется обычный расчёт исходного блока.

На листе гранулометрического состава применяется то же правило: дополнительные строки сухого и обводнённого подблоков появляются только для блока, в котором присутствуют обе части.

## Третье графическое приложение — геолого-литологический разрез

Создаётся файл:

```text
`data/output/geological_lithological_section.dxf`
```

На текущем этапе линия разреза задаётся автоматически: скважины используются в том же порядке, в каком они находятся в `Deposit`, то есть в порядке исходного журнала. Это временное решение до добавления отдельного выбора линии разреза пользователем.

Горизонтальные расстояния между соседними скважинами рассчитываются по их фактическим координатам на плане, поэтому горизонтальный масштаб разреза соответствует масштабу плана.

Вертикальная часть построения использует ту же детализацию по глубине, что и геологические колонки.

Для каждой скважины на разрез переносятся интервалы образцов. Одинаковое название породы получает один и тот же CAD-слой `SECTION_LITHO_N` во всём разрезе. При совпадении породы и пересечении интервалов по абсолютным отметкам между соседними скважинами строится замкнутый контур соответствующего слоя.

Фактический уровень грунтовых вод каждой скважины также переносится на разрез синей штриховой линией. Расчётный средний УГВ месторождения для этой графики не используется.

Полноценная условная легенда и окончательная система цветов литологических разновидностей пока намеренно не добавляются — это следующий этап графической доработки.

## Изменения для версии отчёта: лист 7 и ГОСТ 8736-2025

### Лист 7 — «Т. 6»

Сводная таблица заполняется с строки 6. Перед формированием Excel-программа запрашивает для каждого исходного блока:
- площадь блока в м²;
- категорию запасов.

Для сухого и обводнённого подблоков площадь и категория наследуются от исходного блока.

Объёмы записываются в тыс. м³: площадь × средняя мощность / 1000.

ПГС по ГОСТ 31426-2010 и геологический коэффициент вскрыши пока намеренно не рассчитываются.

### Лист 5 — класс песка по ГОСТ 8736-2025

В колонке 23 определяется класс песка прежде всего по модулю крупности. Для классов «Повышенной крупности», «Крупный», «Средний», «Мелкий» и «Очень мелкий» дополнительно проверяется полный остаток на сите 0,63 мм. Результат проверки записывается в колонку 24.

Для «Тонкого» и «Очень тонкого» полный остаток на сите 0,63 мм по указанным требованиям не нормируется, поэтому колонка 24 остаётся пустой.

## Автоматическое определение площади и категории запасов — текущая версия

Для сводной таблицы листа 7 пользователь больше не вводит площадь блока и категорию запасов.

### Площадь блока

Площадь рассчитывается автоматически по координатам всех скважин, входящих в блок.
За крайние скважины принимаются вершины выпуклой оболочки множества координат скважин блока.
Площадь полигона рассчитывается в квадратных метрах по координатам СК-1963 без округления исходных координат.

Если в блоке меньше трёх различных скважин с корректными координатами СК-1963, площадь равна 0 м².

### Категория запасов

Категория извлекается из обозначения блока:

- `IIIB` → блок `III`, категория `B`;
- `IVC1` → блок `IV`, категория `C1`.

Поэтому ручной ввод категории в консоли больше не выполняется.

### Таблица 1

В столбце с номерами блоков обозначения выводятся в разделённом виде:

- `IIIB` → `III B`;
- `IVC1` → `IV C1`.

Если скважина относится к нескольким блокам, все обозначения сохраняются в одной ячейке через запятую.

## Контуры блоков и расчёт площади

В текущей версии программа поддерживает два режима определения площади блока:

1. **Автоматический** — строится выпуклая оболочка всех скважин блока. Это удобный автоматический вариант, но он может завышать площадь, если фактический геологический контур имеет вогнутые участки.
2. **Ручной** — пользователь для каждого блока задаёт крайние скважины в порядке обхода фактического контура. Площадь рассчитывается по этому замкнутому полигону методом Гаусса (shoelace). Этот же контур используется во втором графическом приложении DWG.

Ручной режим рекомендуется использовать для окончательного подсчёта площади, когда фактическая граница блока известна по геологической схеме.

### Контуры на плане

Контуры блоков выводятся только во втором графическом приложении `block_plan.dwg`.
Порядок скважин ручного контура, введённый пользователем для расчёта площади,
используется без изменения и для построения соответствующей замкнутой полилинии.
У автоматического режима полилиния строится по выпуклой оболочке скважин блока.

Условные обозначения категорий:

- категория **B** — `DASHED`, штриховая линия;
- категория **C1** — `DASHDOT`, штрихпунктирная линия с одной точкой;
- категория **C2** — `DASHDOTDOT`, штрихпунктирная линия с двумя точками.

### `boreholes.dxf`

- абсолютная отметка устья;
- мощность вскрыши и ПРС;
- общая мощность полезного ископаемого;
- мощность сухого полезного ископаемого;
- мощность обводнённого полезного ископаемого;
- глубина грунтовых вод.

Средневзвешенные параметры рассчитываются тем же `WeightedAverageCalculator`,
который используется в Excel-части программы, и учитывают только фактически
принятые интервалы соответствующей части ПИ.

### `block_plan.dwg`

Второе графическое приложение создаётся в DWG и использует тот же построитель
плана, что и `boreholes.dxf`. Дополнительно добавляются контуры блоков.

Контуры строятся:

- по заданным крайним скважинам, если выбран `ManualBoundary`;
- автоматически по выпуклой оболочке скважин блока, если выбран
  `AutomaticConvexHull`.

Каждый контур записывается одной замкнутой `LWPOLYLINE`. Тип линии назначается
слою контура в соответствии с категорией блока: B — штриховая, C1 —
штрихпунктирная, C2 — штрихпунктирная с двумя точками.

В DWG также выводятся все подписи скважин, используемые на плане: номер,
отметка устья, мощности вскрыши/ПРС, общей, сухой и обводнённой частей ПИ
и глубина грунтовых вод. Средневзвешенные лабораторные характеристики
в графическую подпись скважины не выводятся, чтобы не перегружать план.

## 13. LibreDWG

Для создания DWG используется свободный проект GNU LibreDWG.

GeoReport не связывается с LibreDWG как с C++-библиотекой напрямую. При сборке
CMake проверяет каталог:

```text
../CppLibs/LibreDWG/
```

Если LibreDWG отсутствует, CMake автоматически клонирует официальный репозиторий
и собирает утилиту `dwgwrite`.

Поэтому ожидаемая структура после первого запуска CMake:

```text
DataHub/
├── CppLibs/
│   ├── OpenXLSX/
│   └── LibreDWG/
└── MyPrograms/
    └── GeoReport/
```

LibreDWG используется для создания DWG версии R2000. Это сознательный выбор:
текущий writer LibreDWG наиболее надёжно поддерживает ранние версии DWG, а
`dwgwrite` документирует запись R2000 как рабочий режим.

### macOS Intel

GeoReport не содержит бинарников LibreDWG. LibreDWG собирается локально на машине
пользователя обычным системным C/C++ toolchain, поэтому MacBook Pro на Intel
поддерживается без отдельной архитектурной версии библиотеки.

LibreDWG подключается к проекту через его собственный CMake-сборщик.
Поэтому GeoReport не запускает `autogen.sh`, `configure` или `make` во время
конфигурации проекта. Это важно для CLion: `Reload CMake Project` должен
завершаться обычной генерацией проекта, а сборка `dwgwrite` выполняется как
часть обычного Build.

На macOS должны быть доступны стандартные инструменты разработки (`git`,
`clang` и `make`). Если Homebrew ещё не содержит базовые инструменты Git,
установите их обычным способом через Homebrew/Xcode Command Line Tools.

### Ручное указание `dwgwrite`

При необходимости можно задать путь к готовой утилите через переменную окружения:

```bash
export GEOREPORT_DWGWRITE=/полный/путь/к/dwgwrite
```

Либо задать `GEOREPORT_LIBREDWG_DIR` в CMake.

## 14. Новые файлы

### `graphics/cad/BoreholePlanDrawingBuilder`

Общий построитель плана. Он гарантирует, что DXF и DWG используют одинаковые
координаты, подписи и показатели.

### `graphics/dwg/DwgPlanWriter`

Создаёт временный DXF-план с контурами и передаёт его `LibreDWG/dwgwrite`,
получая итоговый `block_plan.dwg`.

### `CMakeLists.txt` — интеграция LibreDWG

Проверяет наличие `../CppLibs/LibreDWG`. Если каталога нет, автоматически
клонирует официальный репозиторий. Затем подключает его собственный
`CMakeLists.txt` и собирает цель `dwgwrite`.

## macOS / Intel: LibreDWG memmem compatibility

GeoReport includes `cmake/georeport_memmem_compat.h`. macOS does not expose the GNU `memmem()` function, while LibreDWG uses it in generated parser code. CMake force-includes this small compatibility implementation only while LibreDWG is compiled; the downloaded LibreDWG sources are not modified.

If LibreDWG was already downloaded from an earlier attempt, simply reload CMake and rebuild. There is no need to edit `CppLibs/LibreDWG` manually.


## 11. Графические приложения

Программа формирует три графических результата:

```text
data/output/
├── boreholes.dxf
├── geological_columns.dxf
├── block_plan.dwg
└── geological_lithological_section.dwg
```

### `boreholes.dxf`

План скважин без контуров блоков. На нём остаются номера скважин, отметки устья и основные мощности. Средневзвешенные лабораторные характеристики в подписи скважины не выводятся, чтобы не перегружать графику.

### `block_plan.dwg`

Второе графическое приложение использует те же координаты и скважины, что и `boreholes.dxf`, но дополнительно рисует контуры блоков замкнутыми `LWPOLYLINE`. Тип линии контура определяется категорией блока:

- `B` — `DASHED`, штриховая линия;
- `C1` — `DASHDOT`, штрихпунктирная линия;
- `C2` — `DASHDOTDOT`, штрихпунктирная линия с двумя точками.

Подписи скважин в DWG включают номер и отметку устья.

### `geological_lithological_section.dwg`

Третье графическое приложение теперь также создаётся в DWG. Перед построением пользователь задаёт:

1. количество разрезов;
2. для каждого разреза — номера скважин в порядке их прохождения.

Все выбранные разрезы записываются в один DWG. Горизонтальные расстояния между скважинами рассчитываются по их фактическим координатам SK1963. Вертикальный масштаб сохраняется одинаковым для всех разрезов.

На разрезах выводятся:

- стволы скважин;
- номера скважин;
- отметки устья;
- границы образцов;
- подписи кровли и подошвы образцов в глубинах;
- литологические интервалы и их соединение между соседними скважинами;
- фактический уровень грунтовых вод;
- вертикальная шкала абсолютных отметок;
- номер разреза и список входящих в него скважин.

DWG создаётся через свободную библиотеку LibreDWG и её `dwgwrite`.


## Условные обозначения CAD

При каждом запуске создаётся `data/output/symbols/` с `.lin`-файлами для AutoCAD. В дальнейшем в эту папку будут добавлены `.pat`-заливки пород и другие графические стандарты.

## Геолого-литологический разрез

Разрезы строятся только по выбранным пользователем скважинам. Межскважинное соединение литологических интервалов временно отключено. Для каждой границы интервала подписывается глубина; справа от интервала — номер образца и тип породы; вертикальная шкала содержит абсолютные отметки.

## Текстовая статистика месторождения

При каждом запуске GeoReport дополнительно формируется:

`data/output/deposit_statistics.txt`

Отчёт содержит:

- общую статистику по месторождению;
- количество всех образцов и количество образцов, отнесённых к полезному ископаемому;
- статистику гранулометрического состава по ГОСТ 8736-2025;
- параллельную статистику гранулометрического состава по СП 5.01.04-2025;
- коэффициент фильтрации по каждому классифицированному типу породы;
- минимальное и максимальное значение коэффициента фильтрации с указанием скважины и образца;
- общую характеристику каждого блока;
- отдельную характеристику сухого и обводнённого полезного ископаемого каждого блока;
- распределение образцов по ГОСТ и СП для каждого блока;
- коэффициенты фильтрации для всех образцов и отдельно для образцов ПИ;
- краткую сводку по скважинам блока;
- контроль полноты исходных данных.

Статистика по образцам строится параллельно для двух выборок: всех образцов и образцов,
которые пересекают принятую геологическую модель полезного ископаемого. Для сухой и
обводнённой частей ПИ используются отдельные выборки.
